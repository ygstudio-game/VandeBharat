Metric 1

Health Score

Per-coach structural health as a percentage — shown in the Inspection Hierarchy panel and Report workspace.

Where it appears: Left sidebar of the Report workspace ("Health Score" progress bar), TrainWorkspace AI Intelligence Feed, and the Sessions list card.

Health Score Formula

Backend primary · Frontend fallback
Inputs health_score (from backend coach record), or
defects.length — total number of defects detected for the coach
OutputInteger percentage, 0 – 100 (clamped)
// Backend provides score when available healthScore = coachData.health_score // Frontend fallback when backend score is absent if (healthScore == null) { healthScore = defects.length === 0 ? 100 : Math.max(0, 100 - defects.length × 15) } displayed = Math.round(healthScore)
Example A — Backend score available
Backend returns: health_score = 78.4
Displayed: 78%
Example B — Frontend fallback (3 defects)
Backend health_score: null
defects.length = 3
100 − (3 × 15) = 100 − 45 = 55
Displayed: 55%
Example C — 8 defects (floor applied)
100 − (8 × 15) = 100 − 120 = −20 → clamped to 0
Displayed: 0%

Metric 2

Compliance Score

Structural checklist pass rate — how many required components are present.

Compliance Score Formula

Frontend computed
Input missing.length — count of components flagged as missing / not detected for the active coach
OutputInteger percentage, 0 – 100 (clamped)
complianceScore = missing.length === 0 ? 100 : Math.max(0, 100 - missing.length × 10)
Example — 4 missing components
missing.length = 4
100 − (4 × 10) = 100 − 40 = 60
Displayed: 60%

Metric 3

Stress Score

Risk-tier indicator derived from the highest severity defect present on the coach.

Stress Score Formula

Frontend computed
Inputs summary.critical — count of CRITICAL severity defects
summary.high — count of HIGH severity defects
OutputFixed score: 70, 50, or 25
stressScore = summary.critical > 0 ? 70 : summary.high > 0 ? 50 : 25 // Score tiers: // 70 — Critical defects present (immediate attention required) // 50 — High severity defects only // 25 — No critical or high defects (nominal)
Example A — 1 critical defect
summary.critical = 1 → condition true
Stress Score: 70
Example B — No critical, 2 high severity
summary.critical = 0, summary.high = 2
Stress Score: 50
Example C — All clear
summary.critical = 0, summary.high = 0
Stress Score: 25

Metric 4

OCR Confidence

Measures how reliably the system read coach placard numbers from video frames. Shown in the Live Queue card, header stats, and TrainWorkspace.

OCR Confidence Display

Backend computed · Frontend displays
Source Backend field: session.ocr_confidence (decimal 0.0 – 1.0).
Computed by the OCR stage using PaddleOCR + YOLO-OCR-ROI agreement scores.
Frontend formula Multiply by 100 and truncate to integer
// Normalisation (api.js) ocrConfidence = Number(s.ocr_confidence) // stored as-is (0–1) // Display (LiveTrainCard.jsx) displayed = (session.stats.ocrConfidence × 100).toFixed(0) + '%' // Header (TrainWorkspace.jsx) displayed = (session.ocrConfidence × 100).toFixed(1) + '%'
Example
Backend: ocr_confidence = 0.873
Live Queue card: 0.873 × 100 = 87.3 → 87%
Workspace header: 0.873 × 100 = 87.3 → 87.3%

Metric 6

Detection Confidence (Frame-level)

The highest model confidence score across all detections (components + defects) found in a single frame. Shown in the Detection Log Table on the Reports page.

Frame Confidence Formula

Frontend computed
Inputs frameComponents[] — components detected on this frame, each with c.confidence (0–1)
frameDefects[] — defects detected on this frame, each with d.confidence (0–1)
OutputString percentage "87%", or "—" if no detections
// Collect all confidence values on this frame allConfs = [ ...frameComponents.map(c => c.confidence || 0), ...frameDefects.map(d => d.confidence || 0), ] // Take the maximum maxConf = allConfs.length > 0 ? Math.max(...allConfs) : 0 // Convert to display string displayed = maxConf > 0 ? Math.round(maxConf × 100) + '%' : '—'
Example — mixed detections on Frame #142
Components detected: [0.87, 0.91, 0.63]
Defects detected: [0.76]
allConfs = [0.87, 0.91, 0.63, 0.76]
maxConf = Math.max(...) = 0.91
Math.round(0.91 × 100) = 91
Displayed in CONF column: 91%
Example — no detections on Frame #143
frameComponents = [], frameDefects = []
allConfs = [], maxConf = 0
Displayed in CONF column: —

Metric 7

Frame Extraction Progress

Live progress bar shown on the Pipeline Progress view during the Frame Extraction stage.

Extraction Progress %

Frontend computed
Inputs totalFrames — frames confirmed saved to DB so far
statsUploaded — pipeline_stages.stats.frames_uploaded from the extractor flush
statsVideoTotal — raw total frames in the original video
// Use the larger of uploaded or DB count as the expected total expectedFrames = Math.max(statsUploaded, totalFrames) // Calculate percentage, clamped to 100 extractionPct = expectedFrames > 0 ? Math.min(100, Math.round((totalFrames / expectedFrames) × 100)) : 0
Example — mid-extraction
totalFrames (in DB) = 150
statsUploaded = 200, statsVideoTotal = 840
expectedFrames = max(200, 150) = 200
extractionPct = min(100, round(150 / 200 × 100)) = min(100, 75) = 75
Progress bar: 75% — "75% — raw video has 840 frames"

Metric 9

Playhead Position

Video-style scrubber position in the Report workspace — maps the current (coach, frame) position onto a 0–100% timeline.

Playhead % Formula

Frontend computed
Inputs activeCoachIdx — 0-based index of the currently viewed coach
totalCoaches — total number of coaches in the session
currentFrameIdx — 0-based index of selected frame within this coach
coachFramesCount — total frames for this coach
// Share of timeline consumed by completed coaches coachContribution = activeCoachIdx / totalCoaches // Share consumed by frames within the current coach frameContribution = (currentFrameIdx / coachFramesCount) / totalCoaches // Final playhead position playheadPercent = (coachContribution + frameContribution) × 100 // Playback time (derived from session duration) playbackTime = formatTime(Math.floor(playheadPercent / 100 × durationSeconds))
Example — 5 coaches, viewing coach 2 (index 2), frame 15 of 30
coachContribution = 2 / 5 = 0.40
frameContribution = (15 / 30) / 5 = 0.5 / 5 = 0.10
playheadPercent = (0.40 + 0.10) × 100 = 50%
If session duration = 300 s: playbackTime = floor(0.50 × 300) = 150 s = 00:02:30
Playhead at 50%, timer shows 00:02:30 / 00:05:00

Report Status Derivation

Determines whether a completed session report requires supervisor sign-off or is already approved.

Status Logic

Frontend computed
Input criticalDefects — count of CRITICAL severity defects across all coaches in the session
Output"PENDING_SIGNATURE" or "APPROVED"
// Reports.jsx — sessionToReport() status = s.criticalDefects > 0 ? 'PENDING_SIGNATURE' : 'APPROVED'
Example A — 2 critical defects found
criticalDefects = 2 → condition true
Status: PENDING_SIGNATURE (amber badge, requires supervisor PIN)
Example B — no critical defects
criticalDefects = 0 → condition false
Status: APPROVED (green badge, no signature needed)

Summary

All Metrics at a Glance

Quick reference for every accuracy and scoring metric used across the RDSO_MVIS dashboard.

# Metric Formula / Source Range Where Shown Computed by
1 Health Score backend.health_score or max(0, 100 − defects × 15) 0 – 100 % Reports sidebar, TrainWorkspace panel Backend (primary) / Frontend (fallback)
2 Compliance Score max(0, 100 − missing × 10) 0 – 100 % Reports sidebar Frontend
3 Stress Score critical>0 → 70, high>0 → 50, else 25 25 / 50 / 70 Reports sidebar Frontend
4 OCR Confidence ocr_confidence × 100 0 – 100 % Live Queue card, Workspace header Backend (PaddleOCR + YOLO-OCR-ROI)
5 Sync Confidence sync_confidence × 100 0 – 100 % Live Queue card Backend (Synchronisation stage)
6 Frame Detection Confidence max(component.conf[], defect.conf[]) × 100 0 – 100 % or — Detection Log Table (CONF column) Frontend
7 Frame Extraction Progress min(100, round(totalFrames / max(uploaded, total) × 100)) 0 – 100 % Pipeline Progress view Frontend
8 Pipeline Progress session.progress_pct (from backend) 0 – 100 % Live Queue card, Pipeline bar Backend
9 Playhead Position (coachIdx/total + frameIdx/frameCount/total) × 100 0 – 100 % Report workspace timeline Frontend
10 Report Status criticalDefects > 0 → PENDING else APPROVED Binary flag Reports list, workspace header Frontend
Note on backend-computed metrics: OCR Confidence, Sync Confidence, and Pipeline Progress are authored entirely by the Python backend pipeline and passed to the frontend as-is. The frontend only converts the decimal values to percentage strings for display. Any recalibration of these scores must be done in the backend OCR / Sync / Stage-completion workers, not in the frontend code.
Confidence scale convention: All model confidence values from YOLO and PaddleOCR are stored internally as decimals (0.0 – 1.0). The frontend always multiplies by 100 before display. Never store or pass these as percentages to the backend.
